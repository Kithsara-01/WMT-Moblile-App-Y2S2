# Vehicle Spare Parts & Service Booking Mobile Application

An Expo / React Native mobile application with a Node.js, Express, and MongoDB backend, developed as a university group project. It brings spare-parts browsing, product management, inventory, orders, reviews, and service bookings into one mobile platform.

## Project Overview

Manual spare-parts and service management can make product availability, stock updates, orders, and bookings difficult to track. This project provides customer and administrative workflows through a mobile frontend and REST API.

**Project type:** University group project  
**Frontend:** React Native with Expo  
**Backend:** Node.js and Express  
**Database:** MongoDB with Mongoose

## Key Features

| Area | Functionality |
| --- | --- |
| Accounts | Registration, login, JWT authentication, and profile retrieval |
| Products | Create, view, update, and delete products; upload images; search, filter, and sort the catalogue |
| Inventory | Stock updates, low-stock queries, and inventory reports |
| Shopping | Cart, checkout, order placement, and order history |
| Orders | Order status management, delivery tracking, cancellation, and refund-related workflows |
| Reviews | Product reviews with create, update, and delete operations |
| Services | Service management, availability checks, bookings, booking updates, and cancellation |
| Payments | PayHere sandbox checkout-session generation |
| Dashboard | Administrative overview and detailed management views |

## Architecture

The mobile application sends HTTP requests to the Express REST API. Controllers handle account, catalogue, inventory, order, review, and service operations using Mongoose models. MongoDB stores application data, while uploaded images are stored in the backend's local `uploads` directory and served through `/uploads`.

PayHere checkout sessions are generated by the backend for the sandbox payment flow.

## Running Locally

### Prerequisites

- A Node.js version compatible with the included Expo SDK 54 and Mongoose 9 dependencies, with npm.
- A MongoDB database, either local or hosted.
- An Expo-compatible device/emulator or development build.
- PayHere sandbox credentials if testing the payment-session flow.

Download or clone this repository, then open terminals in its root folder.

### 1. Configure and start the backend

Create `backend/.env` locally:

```dotenv
PORT=5000
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_long_random_secret
PAYHERE_MERCHANT_ID=your_sandbox_merchant_id
PAYHERE_MERCHANT_SECRET=your_sandbox_merchant_secret
```

Use your own values; never commit this file. The PayHere variables are needed for payment-session generation.

```bash
cd backend
npm ci
npm run dev
```

For normal startup, use `npm start` instead. The default backend port is `5000`. Opening `http://localhost:5000/` should return:

```text
Vehicle Spare Parts API is running...
```

Image uploads recreate the `backend/uploads/` directory when required. Previously uploaded images and database records are not included in this repository.

### 2. Configure and start the mobile frontend

Create `frontend/.env` locally:

```dotenv
EXPO_PUBLIC_API_URL=http://YOUR_COMPUTER_LAN_IP:5000
```

Set the URL to your backend host **without `/api`**; the client adds that path automatically. For a physical phone, use a reachable computer LAN address and keep both devices on the same network. `localhost` on a phone points to the phone itself. For an Android emulator, the host machine is commonly reachable through `http://10.0.2.2:5000`.

In a second terminal:

```bash
cd frontend
npm ci
npm start
```

Use the Expo development server to open the app on a compatible device or emulator. Restart Expo after changing environment variables.

If `EXPO_PUBLIC_API_URL` is absent, the existing client falls back to the Railway URL recorded in the source. Availability of that historical deployment is not guaranteed.

## API Overview

All API routes are registered in `backend/server.js`.

| Base path | Area |
| --- | --- |
| `/api/auth` | Registration, login, and profile |
| `/api/products` | Product catalogue and management |
| `/api/inventory` | Stock, low-stock queries, and reports |
| `/api/orders` | Customer and administrative order operations |
| `/api/reviews` | Product feedback |
| `/api/services` | Services, availability, and bookings |
| `/api/payments` | PayHere sandbox session generation |
| `/api/dashboard` | Administrative overview and details |

Protected routes expect:

```http
Authorization: Bearer <your_jwt_token>
```

Example public catalogue requests:

```http
GET /api/products
GET /api/products?search=brake&sort=price_asc
GET /api/products/top-rated
```

Product create/update requests support multipart form data with an `image` field. Refer to the route and controller files for exact request fields and authorization behavior.

## Implementation Notes

- This is an academic project snapshot; this README does not claim production readiness or a newly verified live deployment.
- The delivery scheduler advances eligible orders approximately every 10 seconds for demonstration purposes. It is not connected to a courier service.
- Payment integration targets PayHere Sandbox. The session payload currently contains localhost return/cancel/notify URLs, and the uploaded route set does not include a PayHere notification handler. It should not be presented as production payment verification.
- JWT protection is implemented, with admin checks on selected dashboard, order, and service routes. Product and inventory routes currently require authentication without an admin-only middleware check. Public registration also accepts a role value; role assignment needs hardening before production use.
- The backend `npm test` script is a placeholder that exits with an error. No automated test suite is included in this snapshot.
- Uploaded images use local disk storage. Existing upload files, credentials, Expo cache, and dependency folders have been excluded from the public upload copy.
